LayoutKit Docs

A tiny pure-CSS layout vocabulary for readable app structure. Use lk-* tags to make layout intent visible while native semantic HTML carries document meaning. Package version 1.5.0. Types ship in jsx.d.ts.

Install and load CSS

Load LayoutKit early in the document <head>, or import it at the root/global CSS level in a framework. If the CSS does not load, lk-* tags are plain unknown elements.

npm install layoutkit-css
import "layoutkit-css/layoutkit.css";
<link rel="stylesheet" href="https://unpkg.com/layoutkit-css/layoutkit.css">

Scope

LayoutKit covers common layout primitives: stack, row, center, spread, grid, box, card, cluster, switcher, sidebar, cover, spacer, divider, aspect ratio, scroll area, progress, popover, disclosure, and menu. Container queries, subgrid, snap, sticky, and anchors are opt-in.

Non-goals

No buttons, forms, typography system, color themes, icons, animation system, JavaScript behavior, stateful app shell, data table styling, component library, or design system replacement.

Semantic HTML first

LayoutKit is semantic to developers, not to the browser accessibility tree. It should not replace main, nav, section, article, header, footer, headings, buttons, links, lists, tables, or form controls.

Good 
<main>
  <section aria-labelledby="dashboard-heading">
    <lk-stack gap="lg">
      <h1 id="dashboard-heading">Dashboard</h1>
      <article><h2>Open orders</h2></article>
    </lk-stack>
  </section>
</main>
Bad 
<lk-box>
  <lk-stack>
    <lk-box lk-text="2xl">Dashboard</lk-box>
  </lk-stack>
</lk-box>

This loses native document meaning. lk-text is an attribute, not a tag.

Attribute reference

Attributes map to stable layout behavior. They are not a mirror of every CSS property.

Spacing

gap, padding, col-gap, row-gap: none, px, xs through 3xl, and the finite numeric scale.

Alignment

align, justify, place, place-items, and center cover common flex and grid alignment.

Sizing

fill, full-height, width, size, min, and max-h. full-height and lk-cover use 100dvh where supported, then 100svh, then 100vh. --lk-cover-min still overrides the cover.

Grid tracks

responsive and min are both auto-fit, so items grow to fill the row and empty tracks collapse. min sets an enumerated minimum and overrides responsive. Both clamp a track that would be wider than the container. flow on a grid is row, col, or dense. On lk-box and lk-card, flow is the spacing scale.

Divider and frames

The default divider is a currentColor mix, so it stays visible on dark pages. Browsers without color-mix() keep #e5e7eb. Set --lk-divider-color to choose a color. Replaced children of lk-aspect-ratio fill the frame with object-fit: cover.

Opt-in layout

container, subgrid, adapt, snap, slide, sticky, anchor, panel, and scope add behavior only when present. Omitting them keeps the previous layout.

Frozen convenience helpers

lk-card, lk-text, and lk-weight are intentionally small convenience helpers. They are not the start of a component or typography system, and new visual styling primitives should be rejected unless they directly support layout.

Design token customization

LayoutKit variables fall back to default values, but first look for app-level variables such as --space-md, --text-md, and --radius-md.

:root {
  --lk-space-sm: var(--space-sm, 0.5rem);
  --lk-space-md: var(--space-md, 1rem);
  --lk-space-lg: var(--space-lg, 1.5rem);
  --lk-text-md: var(--text-md, 1rem);
  --lk-radius-md: var(--radius-md, 0.75rem);
}

Map LayoutKit to your app tokens. --lk-space-fluid-xs through --lk-space-fluid-3xl are optional clamp lengths. The static scale stays in place until a token points at one, for example --space-md: var(--lk-space-fluid-md).

:root {
  --space-sm: var(--space-2);
  --space-md: var(--space-4);
  --space-lg: var(--space-6);
}

Accessibility

  • LayoutKit wraps and arranges semantic HTML.
  • LayoutKit does not replace semantic HTML.
  • Do not put click handlers on lk-* elements. Use button or a.
  • Do not use lk-* elements as headings, lists, tables, forms, landmarks, or controls.
  • If a LayoutKit wrapper has no semantic purpose, it usually does not need ARIA.
  • Do not add ARIA roles just to make layout wrappers seem semantic.
  • Prefer native HTML first.
  • LayoutKit should not interfere with focus order.
  • Avoid hiding overflow in ways that trap keyboard users.
  • Scroll containers should remain keyboard and screen-reader usable. lk-scroll-area does not create a tab stop. If the region itself must be scrolled from the keyboard, set tabindex="0" and a name on it. Without direction, both axes scroll; direction="vertical" clips inline overflow. A snap carousel follows the same rule. Its direct children are the slides.
  • lk-menu and lk-disclosure do not invent buttons. The menu invoker is the first child and must be a button, link, or summary. Disclosure uses native details.
  • lk-progress is decorative. It does not replace a status message.
  • LayoutKit provides layout behavior only. Accessibility still depends on the underlying HTML and application code.

CSS over JavaScript

These attributes are off until you set them. A browser that lacks the feature keeps the layout you already had.

Container queries

container on lk-switcher measures --lk-switch-at with 100cqi. On lk-sidebar the flexible region uses 50cqi. On lk-grid, fixed cols stack when that grid is under 32rem. container="sm", md, lg, and xl use 24rem, 32rem, 48rem, and 64rem. responsive and min stay auto-fit. limit on a switcher (2–6) stacks every child when there are more than that many.

<lk-grid container cols="3" gap="sm">
  <article>North</article>
  <article>South</article>
  <article>West</article>
</lk-grid>

:has() adaptation

adapt="solo" centers a row or stack that has one element child. place and justify still win. adapt="figure" bleeds a direct child figure and keeps the rest of the card inset.

<lk-row adapt="solo">
  <button type="button">Only action</button>
</lk-row>
<lk-card adapt="figure">
  <figure><img src="/photos/shore.jpg" alt="Rocky shore"></figure>
  <h3>Shore</h3>
</lk-card>

Subgrid

A nested lk-grid with subgrid spans the parent and uses its columns. Keep cols so a browser without subgrid still has a template. subgrid="rows" and subgrid="both" share row tracks. Gap is inherited unless you set one.

<lk-grid cols="3" gap="sm">
  <strong>Name</strong>
  <strong>Status</strong>
  <strong>Updated</strong>
  <lk-grid cols="3" subgrid>
    <span>Website</span>
    <span>Ready</span>
    <span>Today</span>
  </lk-grid>
</lk-grid>

Scroll-snap carousel

snap on lk-row or lk-scroll-area makes each direct child a slide. slide is full, half, third, or peek. direction="vertical" on a scroll area snaps on the block axis. Set tabindex="0" and a name when the region itself must be scrolled from the keyboard.

<lk-row snap slide="peek" tabindex="0" aria-label="Highlights">
  <article><h3>One</h3></article>
  <article><h3>Two</h3></article>
  <article><h3>Three</h3></article>

Sticky sidebar and scroll progress

sticky pins the side panel to --lk-sticky-top (default 0). side="end" pins the last child. lk-progress is a static bar until animation-timeline: scroll() is available. scope="nearest" tracks the nearest scroller. Reduced motion keeps the static bar.

<lk-sidebar sticky>
  <nav aria-label="Sections"><a href="#layouts">Layouts</a></nav>
  <lk-scroll-area max-h="sm" tabindex="0" aria-label="Notes">
    <lk-progress scope="nearest"></lk-progress>
    <p>Notes</p>
  </lk-scroll-area>
</lk-sidebar>

Popover and disclosure

lk-menu expects the invoker as its first child, then an lk-popover with the HTML popover attribute. anchor tethers the panel with position-area where that exists, and leaves the user-agent centered top layer otherwise. lk-disclosure lays out details. panel="overlay" stacks the open panel. anchor tethers it, and the absolute panel remains the fallback. side="end" flips the inline edge.

<lk-menu anchor>
  <button type="button" popovertarget="account-menu">Account</button>
  <lk-popover id="account-menu" popover>
    <nav aria-label="Account"><a href="/install">Install</a></nav>
  </lk-popover>
</lk-menu>
<lk-disclosure panel="overlay" anchor>
  <details>
    <summary>Filters</summary>
    <label><input type="checkbox"> Open</label>
  </details>
</lk-disclosure>

Columns, overlay, and fluid space

lk-columns flows text across cols of 2, 3, or 4. Direct children do not split. overlay on lk-center covers a positioned parent. --lk-space-fluid-xs through --lk-space-fluid-3xl are clamp lengths. They do not change gap until you point a --space-* token at one.

<lk-columns cols="3" gap="lg">
  <p>First point.</p>
  <p>Second point.</p>
  <p>Third point.</p>
</lk-columns>
<lk-switcher limit="2">
  <p>One</p><p>Two</p><p>Three</p>

Using LayoutKit with TSX/JSX

The package includes jsx.d.ts. It only teaches TypeScript about known custom tags and the attributes each one implements. Importing the stylesheet picks up those types. A triple-slash reference works when you do not want compilerOptions.types to replace the automatic @types list.

import "layoutkit-css/layoutkit.css";

/// <reference types="layoutkit-css" />

Browser support

LayoutKit targets modern evergreen browsers with support for custom properties, flexbox, grid, cascade layers, logical properties, aspect-ratio, svh, dvh, min(), object-fit, and color-mix(). Older browsers keep the 100vh and #e5e7eb fallbacks. Container queries, :has(), subgrid, scroll snap, sticky positioning, animation-timeline: scroll(), and anchor positioning (position-area, with inset-area as the earlier name) are opt-in. Each one is wrapped in @supports.

Security and package verification

LayoutKit has no runtime JavaScript, no npm dependencies, no install scripts, no remote imports, and should not perform network requests.
