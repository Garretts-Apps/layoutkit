Name the layout. Leave the arithmetic to the browser.

LayoutKit is one stylesheet of tags such as lk-stack, lk-grid, and lk-frame. A stack is the column and the gap. The min-inline-size: 0 shrink fix is on switcher, sidebar, frame, and scroll area, not on every tag. If you already write CSS on purpose, the rules sit in @layer layoutkit, so a rule you write later, outside that layer, wins. Version 2.1.0. The 2.0 defaults are unchanged.

Install LayoutKit GitHub npm

The same column, two ways

A stack is a column and a gap from the spacing scale. That is the whole tag. Flex children still default to min-inline-size: auto, which is why a long word can blow out a row. Switcher, sidebar, frame, and scroll area set min-inline-size: 0 where a child has to be allowed to shrink. A plain stack does not.

By hand

.stack {
  display: flex;
  flex-direction: column;
  gap: var(--lk-space-md);
}
<div class="stack">
  <h2>Orders</h2>
  <p>128 open</p>
</div>

With the tag

<lk-stack gap="md">
  <h2>Orders</h2>
  <p>128 open</p>
</lk-stack>

If layout is the part you dread

Pick the tag that matches the picture: stack, row, grid, sidebar, switcher, frame. Spacing is xs through 3xl, not a new class for every pixel. The playground renders the same file you ship. There is no JavaScript in the package, and no build step to use it: link the CSS, or import it once.

If you already like CSS

The selectors are attribute selectors in one layer. Container queries measure the component, not the viewport. :has(), subgrid, logical properties, and nesting are used where they are the right tool. @supports wraps what is not in every current browser, including disclosure height animation and customizable selects. You are not buying a skin.

How this differs from the other options

Tailwind

Utilities are good at “this one element, these pixels,” and some people prefer that to naming classes. LayoutKit is the other job: a handful of layout decisions, readable in the markup, with the arithmetic in the stylesheet. It does not replace utilities for one-off paint.

Bootstrap

No button theme and no accordion script. A disclosure is a details element. A menu is a button and a popover. lk-select styles a real select only where appearance: base-select exists. Firefox keeps the system control.

Every Layout

Stack, switcher, sidebar, cluster, cover, and the centered overlay are those algorithms. Every Layout is the book and a set of custom elements. This package is one CSS file you can vendor, with container queries on by default since 2.0 and a frame whose gutters grow instead of a max-width.
INSTALL

Load the CSS early

Link it from the document head, or import it once at the root of a bundler. If the file does not load, nothing in JavaScript reconstructs the layout. The tags stay unknown elements. Features that need a newer engine are skipped by @supports, which is different: the page still works, without the extra motion or the custom select.

npm install layoutkit-css
import "layoutkit-css/layoutkit.css";
<link rel="stylesheet" href="https://unpkg.com/layoutkit-css/layoutkit.css">

Use layout wrappers around semantic HTML

Browsers and assistive technologies do not understand lk-* tags as native landmarks, headings, controls, lists, or forms. Keep the native elements.

<main>
  <section aria-labelledby="dashboard-heading">
    <lk-stack gap="lg">
      <h1 id="dashboard-heading">Dashboard</h1>
      <lk-grid cols="3" responsive>
        <article>
          <h2>Open orders</h2>
          <p>128</p>
        </article>
      </lk-grid>
    </lk-stack>
  </section>
</main>

Accessibility guidance

Use native HTML first. Do not put click handlers on lk-* elements; use button or a.

Do not add ARIA roles just to make layout wrappers seem semantic. If a wrapper has no semantic purpose, it usually does not need ARIA.

LayoutKit should not change focus order. Avoid hidden overflow that traps keyboard users, and keep scroll containers usable.
